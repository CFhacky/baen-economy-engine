## Capability-by-capability adoption matrix

Every observation in the third column is SOURCE-DERIVED. Every future engineering choice in the fourth column is MODEL-PROPOSED unless explicitly marked otherwise.

| Capability | Code locator | Observed implementation | Candidate treatment and required proof |
|---|---|---|---|
| Population / needs | V1 `Economy`, `get_orders_everyone` | Population, stock, unconsumed stock and profession/universal demand are separate state. | ADAPT representation, not starting population or demand coefficients. Preserve distinct populations and their source dates; missing census data is not zero. |
| Profession / workforce allocation | V1 `get_production` | Labor share times population supplies worker count; output includes relative/absolute scale factors. | ADAPT only after source-backed workforce allocation is known. Do not import scale multipliers or assume every resident is a worker. |
| Skills / productivity | B2 `resolveProduction` | Checks a named profession, eligible location, working tool and recipe inputs; some hired labor uses its employer's profession. | ADAPT constraint checks. Correction: inspected code does not implement the numeric skill-threshold rule claimed in the preceding matrix. Numeric GURPS skill handling remains campaign-specific. |
| Natural resources | V1 `replenish` | Resource-derived per-year value is used as a stock floor with `max`; the shown routine is not a finite-deposit depletion ledger. | DEFER direct adoption. An ore body, renewable forest and reservoir require different source-backed stock rules. Do not silently replenish a mined reserve. |
| Recipes / production chains | U1 `ProductionLine`; U2 `_get_chain` | Explicit consumed/produced resources and production time; recursively calculates alternatives and input ratios. | ADAPT declarative recipes with source provenance. Test cycles, co-products, missing inputs and unit consistency before calling the graph executable. |
| Tool degradation | B2 `resolveProduction`, `degradeTools` | Tool-required production refuses broken/missing tools; use reduces durability. Auto-equip consumes replacement stock. | ADAPT maintenance constraints, not default durability/wear. `getToolPerception` says production is halved without tools while the resolver blocks it; local output must agree with mechanics. |
| Storage / reservations | B1 `getInventoryQty`, `reserveInventory`; B3 `expireOrders` | Available quantity excludes reservations; expiration releases sell-order reservations. | ADAPT available/reserved/physical separation. Test over-reservation, duplicate release, negative/NaN requests and atomic failure. Helper clamping is not proof that the whole accounting boundary rejects invalid transfers. |
| Spoilage | B1 `addToInventory`, `checkSpoilage` | Timed perishable stacks disappear and orphaned sell orders are canceled. Reject accidental rejuvenation of old stock and a falsey tick-zero check in a deterministic ledger. Do not add decay to durable assets. |
| Settlement demand | V1 `trade_at_site` | Calculates internal demand before allocating stock toward external orders. | ADAPT reserved local obligations as explicit constraints; no unsourced ration or export priority is a campaign rule. |
