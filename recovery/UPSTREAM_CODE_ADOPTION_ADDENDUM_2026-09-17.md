# Upstream adoption matrix — executable census addendum

This supplements `UPSTREAM_ADOPTION_MATRIX_2026-09-17.md`; it does not ratify the older architecture or select a new campaign model. Public source was read through GitHub's actual file connector at the commits below. No upstream runtime, dependency, or numerical calibration was installed.

## Decision and implementation status

**USER-RULED:** acquire the live Empire sources, retain every record regardless of simulator support, use immutable source evidence and fail closed on incomplete enumeration; no month, Notion write, merge or campaign-time advance.

**SOURCE-DERIVED:** the behavior descriptions in the table below are observations of inspected implementation code. They are not campaign facts or user choices.

**UPSTREAM-ADOPTED:** strict missing-field refusal is used as a behavior-level cross-check in the independently written census acquisition layer. The implementation remains Python standard-library code; no Mesa source was copied or dependency added. The user-mandated no-drop acquisition requirement, rather than an upstream world simulation, determines the census scope.

**MODEL-PROPOSED:** every other unimplemented adoption row in the preceding matrix remains a proposed engineering selection. Its earlier `UPSTREAM-ADOPTED` heading must not be read as user approval or as proof that a module has been ported. Candidate destinations and acceptance tests are not completed implementations.

**UNRESOLVED:** identity-level simulator mapping, campaign-time cutoffs, canonical monetary authority, banking/contract parameters, and record-level source conflicts remain outside this acquisition batch.

## Actual acquisition and validation path

1. The authorized Notion connector directly executed bounded SQL queries and independent count/distinct-UUID/membership/tail queries. Actual receipts are retained in `acquisition/20260917/`; the fuller 79-row Factions capture also has its original direct-tool receipts in `acquisition/20260917-execution/`.
2. `LiveNotionCensusAcquirer.acquire_collection` issues the same read-only tool operations through the host's authorized tool invoker. It checkpoints each page before proceeding, rejects truncation/cursor errors, compares initial and final membership on fresh acquisitions, and retains a failure checkpoint rather than claiming completeness.
3. `tools/materialize_live_census.py` verifies the direct-connector receipts and emits every captured core record. The first batch materialized 293 records; the complete Factions extension brings the cumulative count to 372, with seven retained contextual records additional. Snapshot, preceding-snapshot diff, coverage report and all 21 ledger rows are persisted. This transformation is **not** mislabeled as another live Notion fetch. Subsequent collections remain queued, not claimed acquired.
4. `tools/validate_live_census.py` runs focused tests, the full engine suite, deterministic regeneration and the actual `coverage-check`. Results are reported from execution receipts, not from test-file existence. The coverage gate remains CLOSED.

The 17-column Factions capture preserves Threat Level in addition to every common property from the earlier 16-column capture. `tests/test_live_census_followon.py` verifies live UUID membership, per-record hashes, full-property retention, untyped/tombstone retention, missing-row rejection, terminal-proof rejection and separation of PR validation from branch publication. These are actual executable tests, unlike the explicitly future adapter tests above.

No GPL code was transplanted. No framework rewrite, automatic financial haircut, synthetic source row, blanket capacity value, or campaign parameter was introduced.
